# LP research map: papers, code, and evidence

**Checked 2026-11-16.** This page tracks individual works rather than treating a solver name as a paper. Dates below are the latest revision dates shown by arXiv (unless a journal publication is specified). “Reported effect” means the authors' own experiment or claim. Those figures are **not** comparable across rows. The separately maintained [Mittelmann LPfeas and LPopt tables](LP.md) provide a dated, common-source solver snapshot.

## PDLP line

1. **Applegate, David; Díaz, Mateo; Hinder, Oliver; Lu, Haihao; Lubin, Miles; O'Donoghue, Brendan; Schudy, Warren.** “Practical Large-Scale Linear Programming using Primal-Dual Hybrid Gradient.” *NeurIPS 2021*; [arXiv:2106.04756, v2 (2022-01-07)](https://doi.org/10.48550/arXiv.2106.04756). [Code lineage: FirstOrderLp.jl](https://github.com/google-research/FirstOrderLp.jl). **Method:** PDHG with diagonal preconditioning, presolve, adaptive step sizes, and restarts. **Reported effect:** on 383 MIPLIB 2017 LP relaxations at relative accuracy 1e-8 and a one-hour limit, versus SCS, 6.3× lower geometric-mean solve time and unsolved count falling from 227 to 49. This is the identifiable version of the undated citation of the same title in the supplied list. [Primary source](https://arxiv.org/abs/2106.04756).

2. **Applegate, David; Díaz, Mateo; Hinder, Oliver; Lu, Haihao; Lubin, Miles; O'Donoghue, Brendan; Schudy, Warren.** “PDLP: A Practical First-Order Method for Large-Scale Linear Programming.” [arXiv:2501.07018, v2 (2026-03-18)](https://doi.org/10.48550/arXiv.2501.07018). [C++ implementation in OR-Tools](https://github.com/google/or-tools). **Method:** multithreaded PDLP with feasibility polishing and an eleven-instance, extreme-scale LP collection. **Reported effect:** eight of eleven LPs met a 1% optimality-gap target and primal/dual feasibility errors below 1e-8 within six days on a single machine; the paper reports three solved by each compared Gurobi approach under its stated resource limits. This is a revised, expanded work, not a second run of the 2021 SCS comparison. The arXiv abstract and PDF have differed on the without-polishing ablation count; we omit that count until checked against a fixed version of the full paper. [Primary source](https://arxiv.org/abs/2501.07018).

## cuPDLP line

3. **Lu, Haihao; Yang, Jinwen.** “cuPDLP.jl: A GPU Implementation of Restarted Primal-Dual Hybrid Gradient for Linear Programming in Julia.” [arXiv:2311.12180, v4 (2024-06-07)](https://doi.org/10.48550/arXiv.2311.12180). [Julia code](https://github.com/jinwen-yang/cuPDLP.jl). **Method:** restarted PDHG on NVIDIA GPUs. **Reported effect:** comparable performance to Gurobi on the authors' standard LP benchmark sets; the abstract does not give one universal speedup, so none is quoted here. This resolves the undated `cuPDLP.Jl` software citation in the supplied list. [Primary source](https://arxiv.org/abs/2311.12180).

4. **Lu, Haihao; Yang, Jinwen; Hu, Haodong; Huangfu, Qi; Liu, Jinsong; Liu, Tianhao; Ye, Yinyu; Zhang, Chuwen; Ge, Dongdong.** “cuPDLP-C: A Strengthened Implementation of cuPDLP for Linear Programming by C language.” [arXiv:2312.14832, v2 (2024-01-07)](https://doi.org/10.48550/arXiv.2312.14832). **Method:** C reimplementation and systems optimization of cuPDLP. **Reported effect:** the authors report substantial advantages on large LPs against commercial solvers but the abstract supplies no single controlled speedup. [Primary source](https://arxiv.org/abs/2312.14832).

5. **Lu, Haihao; Yang, Jinwen.** “Restarted Halpern PDHG for Linear Programming.” [arXiv:2407.16144, v2 (2024-09-09)](https://doi.org/10.48550/arXiv.2407.16144). **Method:** rHPDHG and reflected r²HPDHG; accelerated theoretical rates and infeasibility certificates. **Reported effect:** improved numerical performance relative to cuPDLP.jl on 383 MIPLIB instances, with no single aggregate speedup in the abstract. [Primary source](https://arxiv.org/abs/2407.16144).

6. **Lu, Haihao; Peng, Zedong; Yang, Jinwen.** “cuPDLPx: A Further Enhanced GPU-Based First-Order Solver for Linear Programming.” [arXiv:2507.14051, v4 (2025-09-23)](https://doi.org/10.48550/arXiv.2507.14051). [C solver and Python/Julia interfaces](https://github.com/MIT-Lu-Lab/cuPDLPx); [Python package](https://pypi.org/project/cupdlpx/0.3.0/). **Method:** restarted Halpern PDHG, a new restart criterion, and PID-controlled primal weight. **Reported effect:** 2.5–5× against earlier cuPDLP on MIPLIB LP relaxations and 3–6.8× on the paper's Mittelmann set, varying by tolerance and presolve. `cupdlpx` 0.3.0 is a package release, not an additional research paper. [Primary source](https://arxiv.org/abs/2507.14051).

7. **Lu, Haihao; Yang, Jinwen.** “An Overview of GPU-based First-Order Methods for Linear Programming and Extensions.” [arXiv:2506.02174 (2025-06-02)](https://doi.org/10.48550/arXiv.2506.02174). **Type:** survey, covering PDHG, cuPDLP, restarts, preconditioning, Halpern acceleration, infeasibility, and extensions to QP/conic/SDP/NLP. **Effect:** synthesis of prior experiments; do not count as a new independent benchmark. [Primary source](https://arxiv.org/abs/2506.02174).

## HPR-LP line

8. **Chen, Kaihuang; Sun, Defeng; Yuan, Yancheng; Zhang, Guojun; Zhao, Xinyuan.** “HPR-LP: An implementation of an HPR method for solving linear programming.” [arXiv:2408.12179, v2 (2025-03-15)](https://doi.org/10.48550/arXiv.2408.12179). [Julia solver](https://github.com/PolyU-IOR/HPR-LP); [C/GPU solver](https://github.com/PolyU-IOR/HPR-LP-C). **Method:** semi-proximal Halpern Peaceman–Rachford with adaptive restart and penalty updates. **Reported effect:** on the authors' A100 experiments at 1e-8 tolerance, Julia HPR-LP achieves 2.39–5.70× SGM10 speedup over PDLP with presolve and 2.03–4.06× without it, depending on dataset. These are paper-specific comparisons; the later Mittelmann HPR-LP-C entry is another implementation/version. [Primary source](https://arxiv.org/abs/2408.12179).

9. **Chen, Kaihuang; Sun, Defeng; Yuan, Yancheng; Zhang, Guojun; Zhao, Xinyuan.** “On the Relationships among GPU-Accelerated First-Order Methods for Solving Linear Programming.” [arXiv:2509.23903, v2 (2025-10-01)](https://doi.org/10.48550/arXiv.2509.23903). **Method:** theoretical relationship of HPR-LP, cuPDLPx, and EPR-LP plus numerical tests. **Reported effect:** the authors report the best overall GPU result for HPR-LP on their tested data, but the arXiv abstract provides no transferable aggregate number. Treat the algorithmic relationship as the paper's claim, not evidence that the released codebases are interchangeable. [Primary source](https://arxiv.org/abs/2509.23903).

10. **Chen, Kaihuang; Lai, Qilin; Liang, Yijia; Lu, Jiawei; Sun, Defeng; Yuan, Yancheng; Zhang, Guojun; Zhang, Xiangyu; Zhao, Xinyuan.** “Recent Developments in HPR Methods for Large-Scale Linear Programming.” [arXiv:2611.01872 (2026-11-01)](https://arxiv.org/abs/2611.01872). **Method:** GPU preprocessing, scaling, reusable sparse-matrix execution plans, sieving, multi-GPU operation, and model storage around HPR-LP. **Effect:** a methods update; no single speedup is stated in the abstract. [Julia code](https://github.com/PolyU-IOR/HPR-LP); [C/GPU code](https://github.com/PolyU-IOR/HPR-LP-C).

## Presolve and scaling

11. **Cederberg, Daniel; Boyd, Stephen.** “Presolving for GPU-Accelerated First-Order LP Solvers.” [arXiv:2604.23951 (2026-04-27)](https://doi.org/10.48550/arXiv.2604.23951). [PSLP code](https://github.com/dance858/PSLP). **Method:** lightweight CPU presolve designed around end-to-end GPU solve time. **Reported effect:** captures much of the reduction of a commercial presolver at lower presolve cost and improves cuPDLPx end-to-end time; the abstract does not state a universal factor. PSLP is integrated by multiple GPU solver teams according to the paper. [Primary source](https://arxiv.org/abs/2604.23951).

12. **Cederberg, Daniel; Boyd, Stephen.** “GPU-Accelerated Presolving for Linear Programming.” [arXiv:2609.16182 (2026-09-14)](https://doi.org/10.48550/arXiv.2609.16182). **Method:** cuPSLP, a GPU version of PSLP. **Reported effect:** 11× lower shifted-geometric-mean **presolve time** on the authors' Mittelmann set and 42× on GAMS large LPs, compared with PSLP, with similar reduction quality. This does not claim 11× or 42× faster full LP solves. [Primary source](https://arxiv.org/abs/2609.16182).

13. **Gao, Wenzhi; Chu, Ya-Chi; Ye, Yinyu; Udell, Madeleine.** “Gradient Methods with Online Scaling Part I. Theoretical Foundations.” [arXiv:2505.23081, v2 (2025-09-05)](https://doi.org/10.48550/arXiv.2505.23081). **Method:** online-learning-based step-size adaptation for smooth convex optimization. **LP relevance:** conceptual preconditioning/step-size background, not a tested LP solver. **Effect:** theoretical convergence guarantees; no LP benchmark result to compare. [Primary source](https://arxiv.org/abs/2505.23081).

14. **Lu, Haihao; Zhang, Wanyu.** “Enhanced PDHG for Linear Programming with Online Preconditioning.” [arXiv:2506.17650 (2025-06-21)](https://doi.org/10.48550/arXiv.2506.17650). [cuPDLP.jl base code](https://github.com/jinwen-yang/cuPDLP.jl). **Method:** adaptive primal/dual preconditioners with normalized online losses and infrequent updates. **Reported effect:** fewer iterations and shorter solve times on standard LP datasets in the authors' experiments; no universal factor in the abstract. [Primary source](https://arxiv.org/abs/2506.17650).

## Crossover and theory

15. **Liu, Tianhao; Lu, Haihao.** “A New Crossover Algorithm for LP Inspired by the Spiral Dynamic of PDHG.” [arXiv:2409.14715, v2 (2025-08-04)](https://doi.org/10.48550/arXiv.2409.14715); [journal DOI](https://doi.org/10.1287/ijoc.2024.0996). **Method:** recover a vertex/basis solution from an optimal LP solution using PDHG spiral dynamics. **Effect:** numerical experiments support crossover effectiveness; this is a different endpoint from finding a feasible point and has no benchmark-wide factor in the abstract. [Primary source](https://arxiv.org/abs/2409.14715).

16. **Lu, Haihao; Yang, Jinwen.** “On the geometry and refined rate of primal–dual hybrid gradient for linear programming.” *Mathematical Programming* **212** (2025), 349–387; [DOI](https://doi.org/10.1007/s10107-024-02109-9). **Method:** two-stage convergence and active-variable identification analysis using a local sharpness quantity rather than a global Hoffman constant. **Effect:** a theoretical result; no solve-time ranking should be inferred. Published online 2024-07-17 and assigned to the 2025 volume. [Publisher source](https://link.springer.com/article/10.1007/s10107-024-02109-9).

## Conic, infeasibility, and distributed extensions

17. **Lin, Zhenwei; Xiong, Zikai; Ge, Dongdong; Ye, Yinyu.** “A Practical GPU-Enhanced Matrix-Free Primal-Dual Method for Large-Scale Conic Programs.” [arXiv:2505.00311, v4 (2026-10-28)](https://doi.org/10.48550/arXiv.2505.00311). **Method:** PDCS/cuPDCS, a reflected restarted Halpern PDHG variant for LP, SOCP, convex QP, and exponential cones. **Reported effect:** better efficiency and scalability on the authors' large conic applications and CBLIB experiments; it belongs in future conic sections too. The supplied citation's 2026-04-01 date refers to v3, not the current v4. [Primary source](https://arxiv.org/abs/2505.00311).

18. **Lu, Haihao; Tang, Bo.** “H-PDLP: GPU-Accelerated Linear Programming via Generalized PDHG and Homogeneous Self-Dual Embedding.” [arXiv:2610.17695 (2026-10-13)](https://doi.org/10.48550/arXiv.2610.17695). [Code](https://github.com/MIT-Lu-Lab/H-PDLP). **Method:** homogeneous self-dual embedding to return LP solutions or infeasibility/unboundedness certificates. **Reported effect:** introduces MIPLIBInfeas with 229 infeasible and 105 unbounded LPs; the abstract reports successful tests but no one-number speedup. [Primary source](https://arxiv.org/abs/2610.17695).

19. **Deza, Arnaud; Dey, Santanu S.; Van Hentenryck, Pascal.** “Distributed Linear Programming on GPU Clusters at Extreme Scale.” [arXiv:2609.09108, v2 (2026-11-08)](https://doi.org/10.48550/arXiv.2609.09108). [SHARDLP code](https://github.com/ArnaudDeza/ShardLP). **Method:** sharded LP data and PDHG state across GPU nodes. **Reported effect:** ten of eleven Google PDLP large-scale instances solved; a 1.185-billion-variable, 6.338-billion-nonzero case takes 9.9 minutes of solver time on eight H200 GPUs. The paper's CPU reference uses different hardware, so it is not a controlled speedup. [Primary source](https://arxiv.org/abs/2609.09108).

## Maintenance notes

- Use the latest paper version for bibliographic metadata, and retain the specific version for any quoted experiment.
- A paper, its software repository, and a package release are linked records, not three independent algorithmic works.
- Keep author-reported speedups beside their own baselines and settings. For cross-solver snapshots, use [LPfeas and LPopt](LP.md) and preserve the source's separate CPU/GPU groups.
- Open-source availability is attached to a specific repository; commercial benchmark participants such as COPT and MOSEK are never described as open source.
